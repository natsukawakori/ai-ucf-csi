# 系统模型与评测口径

本文说明「数据怎么来、系统怎么算、评测怎么保证正确」，是复现与审阅的唯一口径来源。
结果数字见 [结果与统计.md](结果与统计.md)。

---

## 1. 数据

### 1.1 来源

- 场景：DeepMIMO `O1_3p5`（Remcom Wireless Insite 射线追踪，3.5 GHz，4 次反射）
- 场景结构：主街（550 m × 36 m）+ 横街（x 方向 220 m 与 135 m，两条 36 m 宽带），构成「十」字
- 基站：18 个，高 6 m；主街两侧各 6 个（x = 235.5 / 287.5 m，相距 52 m），
  横街两端各 3 个（x = 38.1 / 188.1 / 338.1 m）
- 用户网格：3 个（主街 497,931 点；横街西 199,281 点；横街东 487,711 点）

本项目只使用**主街网格**（`--rx-grid 0`），随机抽取 8000 个用户，按 y 坐标做 60/20/20
空间切分（训练/验证/测试用户互不重叠）。

### 1.2 阵列合成

场景中每个基站只有 1 根天线。为使多天线预编码有意义，用每条径的**发端离开角**合成
4 天线半波长 ULA：

```
H[k,l,a,n] = Σ_p sqrt(P_p) · exp( j(φ_p − 2π f_n τ_p) ) · exp( j π a sin θ_p )
f_n = f_c + (n − (Nf−1)/2) · Δf,   Δf = B / Nf
```

约定与取舍：

- 阵列朝向取全局 x 轴（射线数据不含阵列姿态），这一选择只改变空间图样的绝对朝向；
- 缺失径在原始数据中用 NaN 填充（约 50%），必须显式清洗，否则整张矩阵变 NaN；
- 仅用于计算 CSI，不引入任何非物理增益。

### 1.3 几何事实与口径影响

横街 6 个 AP 的 β 中位数比主街 AP 低约 **22 dB**，在 Top-6 候选集中出现率仅
**1.7%（测试）/ 22%（训练，靠近路口）**，从未成为"最强 AP"。

因此：**名义 L = 18，有效参与服务的 AP 约 12**。报表中的"负载 K·S/L = 3"是名义值，
按 12 个工作站点估算约 **4.5**。这一点影响对干扰密度的解读，必须在引用结果时一并说明。

## 2. 系统模型

| 符号 | 含义 | 主口径取值 |
| --- | --- | --- |
| L | AP 数 | 18 |
| K | 用户数 | 18 |
| Na | 每 AP 天线数 | 4 |
| Nf | 子载波数 | 32 |
| M | 候选 AP 数（按大尺度增益 Top-M） | 6 |
| S | 实际服务 AP 数（候选内 Top-S） | 3 |
| P_AP | 每 AP 功率 | 0.1 W |
| B / f_c / NF | 带宽 / 载频 / 噪声系数 | 10 MHz / 3.5 GHz / 7 dB |

### 2.1 反馈预算

```
总比特 = M × (d × q + q_p) + ⌈log₂ C(M, S)⌉
```

- `d`：每条链路的实数码字维数；`q = 8` bit/维；`q_p = 8` bit 功率；末项为服务集索引。
- M=6, S=3 → 末项 5 bit；d=8 → **437 bit**，d=32 → **1589 bit**。
- 原始 CSI 每条链路 2×4×32 个复数，按 float32 计 8192 bit → 压缩比约 1/19 与 1/5。
- 不含导频与协议冗余。

### 2.2 预编码

- **MRT**：`w_{l,k} = h_{l,k} / ||h_{l,k}|| · sqrt(p_{l,k})`
- **RZF**（逐 AP，支持集约束）：在每个 AP 服务的用户集合上解
  `W_l = H_l (H_l^H H_l + α I)^{-1}`，再逐链路功率归一；
  `α = κ · |U_l| · σ² / P`，κ 为主扫描量。
- 未服务链路严格为 0；每 AP 每子载波总功率恒为 `P_AP / Nf`。
- RZF 只抑制**本 AP 内**的多用户干扰（与 LP-MMSE 同族），不处理簇外干扰。

### 2.3 功率策略

在波束方向不变的前提下重新分配各 AP 的功率：`equal`（均分）、`gain`（按瞬时链路增益，
用重建信道计算，现实可实现）、`beta`（按大尺度增益，含真值信息，仅作参考）。

### 2.4 评价指标

- **SE**：多 AP 相干合成下逐用户 SINR → 香农速率，再对用户求和；
- **p5**：尾部分位数。注意两种口径不可混用——
  "按快照×用户样本"与"按用户槽位跨快照平均"含义不同；
- **NMSE**：以 `csi.nmse_db`（能量加权）为主报口径，逐链路 dB 均值仅作参考。

## 3. 评测路径的三条不变量

这三条是本项目所有结论的地基，任何评测改动都必须重新验证。

1. **候选编号与信道同序。** 读取批次时，信道张量、候选索引、服务集、码字张量必须用
   同一个排序 `order` 一起搬运。历史上曾出现"信道按原始候选序、索引已排序"的错位：
   恒等自检依然通过（因为两边用同一份错位数据），但绝对 SE 偏低约 2.4 倍，
   且 RZF 与 MRT 的相对强弱被随机打乱。
2. **恒等自检。** 把码字直接当作真实信道（不经过网络）时：NMSE 应 < −140 dB，
   且 `recon` 与 `perfect` 的 SE 必须**逐位相同**。不通过则评测链路有问题，不得出结论。
3. **码字量化必须插在 encode 与 decode 之间。** 评测脚本直接调用 `encode` / `decode`，
   写在模型 `forward` 里的量化不会生效（症状：量化前后结果完全一致）。

---

## 4. 门禁

- 数据构建侧：`K · S ≥ L`（平均每 AP 至少服务 1 个用户）；
- 评测侧：非空干扰链路比例必须 > 0（否则"去蜂窝"退化为孤岛系统）；
- 门禁不通过时脚本直接报错退出，不产出可用于结论的数字。

---

## 5. 不能宣称的边界

1. 单场景、LOS 主导（链路级 72%），未在 NLOS 密集城区验证；
2. 名义 18 站、有效约 12 站；
3. 逐 AP 局部预编码，未做集中式协作或簇间协调；
4. 功率为固定规则，未与波束联合优化；
5. 6 个训练种子只反映训练重复性，不是 6 个独立场景；多重比较未校正；
6. 4 天线为射线角度合成，真实阵列姿态与耦合未建模；
7. 反馈比特数不含导频与协议开销；量化验证的样本量与骨干覆盖有限。
